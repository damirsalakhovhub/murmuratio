# murmuratio

Локальная доска агентов и просмотр сохранённых чатов Codex, расхода токенов и контекста.

После `./murmuratio run` откройте **http://127.0.0.1:8765/**.

## Использование

- **Board** показывает агентов; **Codex chats** открывает сохранённые чаты Codex.
- В Codex найдите чат по названию или пути проекта. По умолчанию архив и субагенты скрыты; включаются отдельно. Недавние чаты загружаются порциями по 60, «Ещё чаты» раскрывает следующую порцию.
- Боковая колонка Codex показывает закреплённые чаты, пользовательские разделы, проекты и недавние чаты. Состав и порядок берутся из локального состояния Codex и обновляются при работе сервиса; проектные чаты могут также присутствовать в недавних. Состояние раскрытия разделов хранится отдельно в браузере инспектора. Поддерживаются локальные чаты этого Mac.
- У выбранного Codex-чата четыре блока: **Контекст**, **Расход**, **Модель**, **Сжатия**. Крупные значения дают обзор; подробности раскрываются внутри блоков. На широком экране — верхний блок и три в строку, на средней ширине — 2×2, на узкой — один столбец. Лента «События чата» по умолчанию свёрнута.
- График в «Контекст» показывает последние 100 обращений; «История запросов» — точные значения. «Состав контекста» — 12 крупнейших сохранённых текстовых блоков текущего сегмента, их оценки и повторы. «Сжатия» показывает значения до/после последнего сжатия, в деталях — до 30 последних сжатий.
- Лента Codex загружается по 120 событий, «Ранее» добавляет предыдущие. Тексты длиннее 16 000 символов раскрываются полностью отдельной кнопкой. Во время работы приходят новые события без пропусков при пакетных обновлениях.
- Ответы и крупные результаты сворачиваются. Чтение выше конца ленты сохраняет позицию.

Ширина списка, фильтры и выбор чатов хранятся в localStorage этого браузера. В другом браузере их нужно настроить отдельно. Эти действия не меняют чаты Codex.

### Board

Первая вкладка **Board** — англоязычная kanban-доска по проектам, например Atlas, Northstar и Harbor. Одна строка заголовка содержит Agents, число работающих агентов, требующих вмешательства и завершённых сегодня; справа — лимиты Claude/Codex и вкладки Board / Codex chats. Дата и время обновления не показываются. Лимиты Claude читаются из кеша инспектора или существующего кеша `~/.claude/tools/claude-limits.json`, Codex — из последних записей `rate_limits` в новых rollout. У каждого инструмента один официальный логотип 32px и кольца 40px для короткого окна и недели. Внешнее кольцо показывает расход с учётом темпа; внутреннее — прошедшее время по часам или дням. Процент сохранён в DOM и скрыт. Рядом — окно и время до сброса; стрелка темпа появляется при наличии истории расхода. У инструмента, которому сегодня идёт код (`routing.json` code_to), вместо логотипа показан строитель: голова в каске (символы `now-claude-builder` / `now-codex-builder` в `web/branding.html`). Логотип на каске — отдельный SVG-слой `g.builder-logo`; его размер и место меняются атрибутом `transform` без перегенерации картинки.

В колонке сначала оркестратор проекта, затем его Claude/Codex-агенты с линиями родства. Карточка показывает папку инициатора или роль, затем модель тем же шрифтом, задачу максимум в две строки, статус с читаемым текущим действием и время. Кольцо контекста снизу справа показывает процент: зелёный до 50%, оранжевый от 50%, красный от 80%. Оркестратор показывает начало текущего хода или время последнего ответа. Значения разделены пробелами или отдельными элементами. Оранжевая обводка и «needs you» появляются у заблокированного оркестратора и у агента, ожидающего разрешения. Оркестратор, завершивший ход, показывает Quiet; если его агенты работают — Idle. Колонка без работающих агентов затемняется до 50%, при наведении возвращается полная яркость. Технические значения набраны системным моноширинным шрифтом. Название задачи Codex открывает просмотр чата; тема следует системной настройке.

Обновление — каждые 3 секунды, пока страница видна. Пока указатель над доской или выделен текст, изменения накапливаются; после чтения применяется последний снимок. Существующие карточки сохраняют порядок, новые добавляются в конец своей колонки. Доска оставляет текущую работу, неархивных оркестраторов и активность текущего местного дня. Завершённые карточки уходят через 30 минут; счётчик «N done» в колонке сохраняет сегодняшний итог. Не сообщаемые сервером карточки и пустые колонки удаляются. Родитель остаётся видимым, пока на доске есть его дети.

Исходные данные сессий только читаются: `~/.claude/tools/codex-runs/*.json`, указанные в них JSONL событий и `~/.claude/projects/*/*.jsonl`. Названия Claude и родство берутся из `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json`; desktop-ID сопоставляется с `cliSessionId`. Архивные сессии скрыты. Родитель Codex — `parent_session` или `parent_app_session`; запасной вариант — проект из `from_cwd`, затем `cwd`/`target`. Верхняя видимая Claude-сессия считается оркестратором, даже если она запущена архивной главной сессией. Одноимённый дочерний «… orchestrator» заменяет предшественника; дети перепривязываются к преемнику. Сессии из `side-session-notes` наследуют колонку своего инициатора.

Завершённый ответ дочерней Claude-сессии означает Done. Иначе изменение Claude за последние 2 минуты означает Running. У Codex проверяется PID: завершённый процесс — Stopped, живой без событий более 10 минут — Stalled; `done` означает Done, вердикт `BLOCKED` — Blocked. Время Running считается от начала сессии/запуска, Quiet — от последнего завершённого ответа, Done — до последнего ответа/`ended`. Исторический ledger без run-файла не используется. Запуски расписания с `scheduledTaskId` в desktop JSON всегда скрыты, включая оркестраторов и дочерние сессии.

История лимитов сохраняется в `~/.claude/tools/limits-history.jsonl` только при изменении расхода или времени сброса, за последние 21 день. `routing.json` рядом содержит распределение кода и дизайна по недельному запасу и среднему расходу последних трёх дней текущего окна. Codex использует только уровни luna/sol. Эти локальные производные данные не меняют настройки или источники чатов.

### Экспериментальный сброс контекста Codex

Откройте инспектор в отдельном браузере, завершите задачи и закройте ChatGPT/Codex и другие процессы Codex. Выберите локальный чат и нажмите **Сбросить контекст** справа от его названия. В окне подтверждения перечислены последствия; действие недоступно, пока Codex открыт или у чата есть активная цель. Не открывайте Codex до окончания операции.

Операция создаёт новое окно контекста через экспериментальные функции встроенного Codex. ID и история сохраняются. В тесте часть старых сообщений также сохранилась в служебном `retained_context`, а доступны ли они модели через историю — не установлено. Поэтому это не доказанный эквивалент нового чата. Автоматические инструкции и окружение могут загружаться снова. Поведение внутреннего протокола после обновлений Codex не гарантируется. При прерывании работы проверьте статус, модель и разрешения чата перед продолжением.

Для измерения сначала вручную отправьте в чате короткий вопрос и дождитесь ответа. После операции откройте Codex и отправьте тот же вопрос без инструментов на той же модели. Инспектор покажет оба замера и разницу, если модель и размер окна совпадают; совпадение текста и инструментов автоматически не проверяется. Контрольные вопросы отправляются только вручную. Для создания окна инспектор временно выбирает Astra, затем восстанавливает модель и профиль разрешений и проверяет их в новом процессе. Работа внутренней команды проверена на конкретной версии Codex; другие версии блокируются до проверки.

## Как понимать показатели

Последний вход — объём прошлого обращения, а не следующего запроса. После сжатия до нового обращения показывается ожидание замера. Накопленные токены включают повторные отправки истории: миллионы потраченных токенов не означают миллионы токенов в текущем окне.

Кеш — часть входа, reasoning — часть выхода. Отсутствующие значения не заменяются нулями. Расход берётся из сохранённых накопленных счётчиков чата; usage отдельных событий повторно не прибавляется. Лимиты подписки — исторический снимок из выбранного чата, не live-запрос аккаунта. Деньги не вычисляются.

Название модели берётся из `turn_context.model`; текущая настройка в списке чатов не подставляется вместо исторической. Явные события перенаправления отображаются, если сохранены. Скрытую внутреннюю версию модели источник не подтверждает.

Оценки блоков — число символов / 4. После compaction анализ текстовых частей начинается с `replacement_history` и базовых инструкций. Зашифрованное резюме и изображения не оценены. Это приблизительный разбор сохранённого контекста, не точный состав сетевого запроса и не «процент мусора». Большой блок может быть полезным. Сравнение до/после сжатия также включает изменения между обращениями.

## Конфигурация и демо

### Установка и запуск

Нужен Python 3.11 или новее. Из каталога проекта:

```sh
./murmuratio install --dry-run             # пути чтения и план изменений
./murmuratio install                       # установить локальную обёртку Claude
./murmuratio doctor           # источники, их состояние и возраст кеша
./murmuratio run              # http://127.0.0.1:8765
./murmuratio run --port 9000
./murmuratio uninstall
```

Установка сохраняет исходный `~/.claude/settings.json` в закрытой резервной копии и добавляет обёртку statusLine. Она передаёт исходный ввод прежней команде и сохраняет её вывод. Без прежней команды выводится `Claude`. Обёртка сохраняет только проценты, время сброса и время снимка в `~/.local/share/murmuratio/claude-limits.json`. Данные приходят от Claude Code при обновлении statusLine, отдельная задача по расписанию и запросы к авторизации не нужны. Старый кеш `~/.claude/tools/claude-limits.json` также поддерживается; используется более свежий снимок. Через 30 минут или после времени сброса снимок помечается как устаревший и не используется для прогноза, но остаётся на доске. `doctor` показывает возраст в секундах.

Конфиг создаётся только при отсутствии и с выключенными дополнительными модулями. Удаление восстанавливает предыдущую statusLine, сохраняет остальные изменения настроек и удаляет каталоги конфигурации и данных, включая прежние каталоги agent-inspector. При неожиданном изменении statusLine или резервной копии удаление останавливается, сохраняя данные для восстановления. `--dry-run` доступен и для остальных команд. Для постоянного запуска на macOS есть отдельный необязательный флаг `./murmuratio install --launch-agent`; без него служба не создаётся. Обёртка и служба используют файлы этого каталога: его нельзя удалять или переносить до удаления установки.

Без `~/.config/murmuratio/config.toml` все дополнительные модули выключены, а проекты группируются по имени папки. Модули включаются отдельно; `context_reset` доступен только вместе с `codex_chats`, а сценарии — вместе с прогнозом. Изменения конфигурации вступают в силу после перезапуска сервера; открытая страница обновится автоматически. Когда сброс выключен, его отметки и замеры не показываются в истории чата.

```toml
[modules]
forecast = true
scenarios = true
routing = true
codex_credits = true
burn_rate = true
codex_chats = true
context_reset = true
codex_wrapper = true
branding = true

[work_hours]
start = 9
end = 21

[paths]
codex_runs = "~/.claude/tools/codex-runs"
routing = "~/.claude/tools/routing.json"
limits_history = "~/.claude/tools/limits-history.jsonl"

[projects]
order = ["Example"]
fallback = "Other"
inherit_folders = ["side-session-notes"]

[[projects.mappings]]
path = "~/projects/example"
name = "Example"
worktrees = true
```

Правила проектов сопоставляют путь и вложенные папки; `worktrees` также включает соседние папки `<path>-worktrees/`. Папки из `inherit_folders` наследуют проект родительского агента; правила с `after_inherit = true` проверяются после них. Несопоставленные пути группируются по имени папки; пустой путь относится к `fallback` (по умолчанию `Unknown`). Проекты вне `order` идут после указанных. При выключенном `routing` файл маршрутизации не читается и не записывается; история лимитов используется только прогнозом и маршрутизацией. С путём к другой конфигурации можно запустить `python3 server.py --config /path/config.toml`.

`python3 server.py --demo --port 8765` показывает неизменяемые данные из `fixtures/demo.json` и не читает конфигурацию, чаты или другие персональные данные. Как в новой конфигурации, все дополнительные модули выключены. Статистика расхода при обычном запуске собирается в фоне и появляется после первого ответа сервера.

## Постоянный запуск

На macOS `./murmuratio install --launch-agent` устанавливает пользовательскую службу, которая запускается при входе и перезапускается после завершения. По умолчанию сервер доступен по `http://127.0.0.1:8765/`; порт меняется через `--port`. Прокси для работы не требуется.

Диагностический запуск: `python3 server.py --port 8765`. Параметр `--codex-home` задаёт отдельный источник; `--data-dir` задаёт каталог данных. При прямом запуске его значение по умолчанию — `.inspector-data/` в каталоге проекта; CLI `./murmuratio run` использует `~/.local/share/murmuratio/`. Сервер также понимает `PORT` и необязательный `PORTLESS_URL`, если прокси уже настроен.

## Источники и приватность

Codex: метаданные `state_5.sqlite` и JSONL rollout только выбранных чатов. SQLite открывается `mode=ro`, `query_only`; пути rollout ограничены каталогами sessions/archived_sessions. Кеш индексов трёх чатов находится только в памяти; при опросе дочитываются новые строки, неполная последняя строка ждёт следующего чтения. Форматы Codex внутренние и могут измениться.

Инспектор не отправляет контрольные вопросы модели сам. Для создания окна он запускает встроенный Codex с MCP, плагинами и приложениями, отключёнными на время процесса; глобальные настройки не меняются. Возможные внутренние сетевые обращения Codex не проверены. Codex изменяет данные выбранного чата. При запуске через CLI инспектор сохраняет состояние операции и замер в `~/.local/share/murmuratio/reset/reset-results.json`; на время операции там также хранятся настройки для восстановления при сбое. Инспектор не читает `auth.json`, cookies или ключи напрямую: авторизацию выполняет сам Codex. Известные шаблоны секретов маскируются; распознать любой произвольный секрет невозможно. Reasoning показывает только сохранённое summary, не encrypted content. HTML из чатов отображается текстом.

Backend слушает loopback; Host/Origin разрешены только для loopback и, при настройке, указанного адреса прокси. В `X-Forwarded-For` проверяется последний адрес, добавленный прокси: внешние адреса отклоняются. Это не защита от программ под тем же пользователем. Общие настройки прокси, DNS, hosts и чужие службы не меняются.

Access log выключен. При прямом запуске результаты сброса хранятся в `.inspector-data/reset/reset-results.json`; прежний файл `reset-results.json` в каталоге данных читается для совместимости. Каталог `reset` закрыт для других пользователей.

## Проверки

```sh
python3 -m unittest discover -v
node --check web/app.js
node --check web/panels.js
node --check web/now.js
```

`npm install` устанавливает зависимость браузерных проверок; затем `npm run test:browser` запускает все три сценария с изолированными временными данными. Требуется Chrome или Chromium; если браузер не найден автоматически, задайте `CHROME_PATH`. Снимки сохраняются внутри `.inspector-data/`; реальные базы тесты не изменяют. Результаты — `VERIFICATION.md`; границы источников — `OBSERVABILITY.md`.

Левую колонку можно расширять перетаскиванием границы. Названия показаны одной строкой; полный текст и проект — при наведении. Избранное временно скрыто.

У строки чата при наведении появляется «Скрыть». Фильтр «Скрытые» показывает убранные чаты с действием «Вернуть». Список скрытых Codex-чатов сохраняется в этом браузере; исходные чаты не изменяются. Поиск работает и среди скрытых; ограничения архива и субагентов в этом режиме не мешают возврату.
